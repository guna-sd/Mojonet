1. Types and Type System

Scalar Numeric Types

  • Int: Signed integer, machine word size (typically 64-bit)
  • UInt: Unsigned integer, machine word size
  • Fixed-precision integers: Int8 to Int256, UInt8 to UInt256
  • Floating-point types: Float16, Float32, Float64

Boolean Type

The Bool type represents True or False values. It supports logical and bitwise NOT operations.

SIMD and Scalars

SIMD (Single Instruction, Multiple Data) types enable efficient, hardware-accelerated vectorized operations:

  • SIMD[DType, width]: Vectorized operations supporting arithmetic, reductions, shuffles, and mathematical functions
  • Scalar[dtype]: 1-element SIMD types with aliases like Float32 and Int64
  • Byte: Alias for SIMD[DType.uint8, 1] (introduced in v24.4) for raw byte data handling

Compile-Time Literal Types

These types represent compile-time constant values:

  • IntLiteral: Arbitrary-precision integers at compile time
  • FloatLiteral: Arbitrary-precision floats at compile time
  • StringLiteral: String literals that materialize into runtime String objects
  • StringSlice and StaticString: Immutable compile-time string data

NoneType

Has a single value, None, used to indicate the absence of a value (e.g., for functions without a return value).

Pointer and Reference Types

Mojo provides both safe and unsafe pointer types with origin tracking for lifetime safety:

  • Safe pointers: Pointer[to=var], OwnedPointer[AnyType], ArcPointer[AnyType]
  • Unsafe pointer: UnsafePointer[AnyType]
  • Non-owning: Pointer[T] points to a T value without ownership

All references and pointers use origin annotations for lifetime safety. The caret operator ^ acts as a transfer operator (move-sigil) and disambiguates assignment from bitwise XOR.

Tuple Types

Tuples group heterogeneous values with compile-time type safety:

var tup = Tuple[Int, Float, String](42, 3.14, "hello")
var value = tup[1]  # Index must be compile-time constant

# Tuple destructuring
var a, b = return_two_values()
(a, b) = (b, a)  # Swap values
_, y = get_pair()  # Discard unwanted elements

2. Collections and Data Structures

List

Dynamic, growable array similar to Python lists. Requirements: elements must be Copyable & Movable.

Key Features:

  • Operations: append(), insert(), pop(), extend()
  • Supports indexing, iteration, and comprehensions
  • Automatic memory management
  • V24.6+ requires explicit .copy() for deep copying
var numbers = List[Int](1, 2, 3, 4, 5)
numbers.append(6)
for item in numbers:
    print(item)

Dict

Hash map with KeyElement keys (hashable and equality-comparable) and Copyable & Movable values.

Characteristics:

  • Open addressing implementation
  • O(1) average-case operations
  • Supports literal creation, insertion, removal, updating, and iteration
  • Performance improvements in v24.4
var scores = Dict[String, Int]()
scores["Alice"] = 95
scores["Bob"] = 87

Set

Unordered collection of unique KeyElement elements. Introduced in v24.1.

Operations:

  • Set operations: union (|), intersection (&), difference (-)
  • Membership testing, adding, removing
  • Backed by Dict for O(1) average-case performance
  • Supports set comprehensions
var primes = Set[Int](2, 3, 5, 7, 11)
var evens = Set[Int](2, 4, 6, 8, 10)
var common = primes & evens  # {2}

Optional

Type-safe wrapper for values that may or may not exist (similar to Rust's Option).

var opt = Optional(42)

# Safe access patterns
if opt:
    print(opt.value())  # Returns reference, aborts if empty

# Provide default value
print(opt.or_else(0))

# V24.4+: copied() for Optional[Pointer[T]]
var ptr_copy = opt_ptr.copied()

Variant (Tagged Union)

Sum type holding one of several Copyable & Movable types at runtime.

var v = Variant[Int, String](42)

# Type checking and access
if v.isa[Int]():
    print(v[Int])

# V24.4+: is_type_supported check
if v.is_type_supported[Float64]():
    v[Float64] = 3.14

String

UTF-8 encoded string type with advanced optimizations:

Optimizations:

  • Small String Optimization (SSO): Stores up to 23 bytes inline on 64-bit systems
  • Copy-on-Write: Lazy copying for efficiency
  • O(1) copying: For short strings that fit in SSO

String Types:

  • String: Owning, mutable
  • StringSlice: Non-owning, immutable view
  • StaticString: Immutable compile-time strings
Note: Converting a constant string literal or StaticString to a String is implicit and avoids runtime allocation.

3. Memory Ownership and Lifetimes

Origins and Lifetime Tracking

Mojo uses origins to track the validity and mutability of references and pointers, ensuring memory safety through compile-time analysis.

Built-in Origin Types:

  • ImmutOrigin: Immutable references
  • MutOrigin: Mutable references
  • Origin[is_mutable]: Parametric mutability

Origin Categories:

  1. Static: StaticConstantOrigin for persistent values (e.g., string literals)
  2. Derived: Created using origin_of(...) at compile time
  3. Inferred: Automatically deduced by the compiler
  4. Wildcard: ImmutAnyOrigin and MutAnyOrigin for references that might access any live value
# Derived origin example
fn create_ref(ref value: Int) -> ref [value] Int:
    return value

# Origin union
fn pick_one(cond: Bool, ref a: String, ref b: String) -> ref [a, b] String:
    return a if cond else b
Critical: The lifetime tracking system prevents destroying values while they're still in use, ensuring memory safety without runtime overhead.

Value Semantics

Mojo distinguishes between two categories of types based on how they're passed:

Register-Passable Types

  • Passed directly in CPU registers (up to 256 bits)
  • Examples: scalars, SIMD types
  • Declared with @register_passable decorator
  • Zero-cost abstraction for small values

Memory-Only Types

  • Involve heap allocation
  • Examples: String, List, large structs
  • Passed by reference or moved

Transfer Operator (^)

The caret operator ^ explicitly transfers ownership, terminating a binding's lifetime:

fn consume(var text: String):
    print(text)

var message = "Hello"
consume(message^)  # Ownership transferred
# message is now invalid - compile error if used

Dual Meaning:

  • As transfer operator: Explicit ownership transfer in function calls and assignments
  • As binary operator: Bitwise XOR on integers
Note: The compiler can elide the ^ operator when it can safely prove ownership transfer is unnecessary (e.g., for temporary values).

ASAP Destruction

Mojo employs As Soon As Possible (ASAP) destruction: values are destroyed immediately after their last use, not at scope end.

fn example():
    var large_data = allocate_large_buffer()
    process(large_data)
    # large_data.__del__() called here immediately
    
    # Continue with other work...
    do_something_else()

Explicit Destruction:

var temp = expensive_resource()
use(temp)
_ = temp  # Force immediate destruction
Benefits: ASAP destruction enables precise resource management, reducing memory pressure and ensuring timely cleanup of external resources like file handles.

4. Attribute System

Attributes provide compile-time metadata that influences compilation without affecting runtime semantics. They use @ syntax and precede declarations.

Attribute Description Use Case
@always_inline Forces function inlining Performance-critical small functions
@__copy_capture Forces closure to copy variables When closure outlives captured values
@noncapturing Indicates no context capture Function pointers, optimization hints
@doc Attaches documentation Documentation generation, IDE tooltips
@deprecated Marks deprecated declarations API migration warnings
@parameter Compile-time execution Metaprogramming, generic functions
@register_passable Enables register passing Small, trivial types (≤256 bits)

Example Usage

@always_inline
fn fast_add(a: Int, b: Int) -> Int:
    return a + b

@parameter
fn compile_time_factorial[n: Int]() -> Int:
    @parameter
    if n <= 1:
        return 1
    return n * compile_time_factorial[n - 1]()

5. Control Flow and Operators

Control Flow Constructs

Conditional Statements

if condition:
    do_something()
elif other_condition:
    do_other()
else:
    do_default()

# Ternary conditional
result = value_if_true if condition else value_if_false

Loops

# While loop
while condition:
    process()
    if early_exit:
        break
    if skip:
        continue

# For loop with iteration
for item in collection:
    process(item)

# For loop with mutable reference (v24.4+)
for ref item in collection:
    item.modify()  # In-place modification
Note: break and continue support arrived in v24.2. For loops iterate over types implementing the Iterable trait.

Compile-Time Loop Unrolling

The @parameter for construct (v24.5+) enables compile-time loop unrolling:

@parameter
for i in range(4):
    # Generates separate code for each iteration
    simd_data[i] = process(simd_data[i])
Requirement: The sequence and induction values must be parameter expressions (compile-time constants).

Walrus Operator (:=)

Assignment expressions within conditions:

if (n := expensive_computation()) > threshold:
    print("Result:", n)

while (line := read_line()):
    process(line)

Operators

Arithmetic Operators

+, -, *, /, %, ** (power)

Comparison Operators

==, !=, <, >, <=, >=

Bitwise Operators

&, |, ^ (XOR), ~ (NOT), <<, >>

Logical Operators

and, or, not

Precedence Note: The ^ operator has higher precedence than addition when used as XOR.

6. Functions and Argument Conventions

Function Declaration Keywords

  • fn: Non-raising functions (default)
  • def: Raising functions (default)

An fn function that might raise must explicitly declare raises in its signature.

fn safe_operation() -> Int:
    return 42

fn risky_operation() raises -> Int:
    if error_condition:
        raise Error("Something went wrong")
    return 42

Argument Conventions

1. read Convention (formerly borrowed)

Passes an immutable reference to the callee. Similar to C++'s const& with Mojo's lifetime safety.

  • Efficient for large values (no copying)
  • Prevents accidental modification
  • Register-passable types pass directly in registers
fn calculate(read data: LargeStruct) -> Int:
    return data.compute()  # Can read, cannot modify

2. mut Convention (formerly inout)

Mutable reference allowing modification of the caller's value.

  • Compiler enforces exclusivity (no aliasing)
  • Enables aggressive optimization
  • Changes are visible to caller
fn increment(mut value: Int):
    value += 1

var x = 5
increment(x)
print(x)  # Prints: 6

3. var Convention (Owned Value)

Function takes exclusive ownership of the value.

  • Caller gives ownership explicitly or a copy is made
  • Function can modify and consume the value
  • Essential for move-only types
fn consume(var text: String):
    text += " (processed)"
    print(text)
    # text is destroyed here

var message = "Hello"
consume(message)  # Copy is made (String is Copyable)
consume(message^)  # Ownership transferred

4. out Convention (v24.6+)

Signals that a function initializes a previously uninitialized value.

  • Used by constructors for self parameter
  • Used for named results/output parameters
  • Caller must not pass an initialized value
fn __init__(out self, value: Int):
    self.data = value
    self.initialized = True

5. owned Convention

Transfers ownership to the callee, ending the value's lifetime at the call site.

  • Function assumes responsibility for destruction
  • Essential for move-only types
  • Transfer operator ^ requests explicit transfer
fn take_ownership(owned resource: UniqueResource):
    use(resource)
    # resource is destroyed when function returns

6. ref Convention

Flexible reference that adapts to the caller's reference type.

  • Mutable caller → mutable access
  • Immutable caller → read-only access
  • Parametric mutability
fn access(ref value: Int) -> Int:
    # Can read, might be able to write depending on caller
    return value

var mut_value = 10
let immut_value = 20
access(mut_value)  # ref is mutable
access(immut_value)  # ref is immutable

7. deinit Convention

Used for destructors and methods responsible for resource cleanup.

  • Value starts initialized
  • Must be consumed or fully deinitialized by return
  • Prevents further destructor calls
fn __deinit__(deinit self):
    release_resources(self.handle)
    # self is in "being destroyed" state

Variadic Arguments

Homogeneous Variadic Arguments

Accept any number of arguments of the same type. Represented internally as VariadicList or VariadicListMem (v24.2+). 

fn sum(*args: Int) -> Int:
    var total = 0
    for arg in args:
        total += arg
    return total

# Usage
print(sum(1, 2, 3, 4, 5))  # 15

# Accessing elements
fn process(*values: Float64):
    for i in range(len(values)):
        print(values[i])
    
    # Apply closure to each element
    values.each[fn()]()

Heterogeneous Variadic Arguments

Accept arguments of different types using a type-list parameter, creating a VariadicPack. 

fn print_all[*Ts: AnyType](*args: *Ts):
    # Process each argument with its specific type
    @parameter
    for i in range(len(args)):
        print(args[i])

Keyword Arguments (Unimplemented)

Planned syntax: **kwargs will pass arbitrary keyword arguments as OwnedKwargsDict[T].

Placement Rule: Variadic positional arguments must follow fixed arguments. Subsequent arguments must be passed by keyword.

Other Argument Types

Default Arguments

fn greet(name: String, greeting: String = "Hello"):
    print(greeting, name)

Keyword Arguments

fn configure(host: String, port: Int, secure: Bool):
    pass

configure(host="localhost", port=8080, secure=True)

Positional-Only Arguments

Indicated by / separator - must be passed by position:

fn compute(x: Int, y: Int, /):
    return x + y

compute(5, 10)  # OK
# compute(x=5, y=10)  # Error

Keyword-Only Arguments (v24.1+)

Achieved using * or variadic parameter - must be passed by name:

fn config(*, debug: Bool, verbose: Bool):
    pass

config(debug=True, verbose=False)  # OK
# config(True, False)  # Error

Parameter System

Mojo's parameter system enables compile-time computation and generic programming. Parameters are enclosed in square brackets and must be compile-time known.

Basic Parameters

fn repeat[count: Int](message: String):
    @parameter
    for i in range(count):
        print(message)

repeat[3]("Hello")  # Prints "Hello" three times

Default Parameter Values

fn foo[a: Int = 42, msg: StringLiteral = "hello"]():
    print(msg, a)

# All valid calls:
foo()                    # Uses defaults
foo[a=7]()              # Partial specification
foo[a=7, msg="hi"]()    # Full specification
foo[msg="test"]()       # Named parameters

Infer-Only Parameters

Parameters declared before // are deduced from context:

fn process[dt: DType, //, value: Scalar[dt]]():
    # dt is inferred from value's type
    print(value)

process(Float32(3.14))  # dt inferred as DType.float32

Automatic Parameterization

Unbound parameters from argument types become implicit compile-time parameters:

fn generic_max[T: Comparable](a: T, b: T) -> T:
    return a if a > b else b

# T is automatically inferred
var result = generic_max(5, 10)  # T = Int
Compile-Time Execution: Functions marked with @parameter execute at compile time, and their results become compile-time constants.

7. Exception Handling

Mojo uses try/except/else/finally for error handling. Functions that may raise must declare raises.

Basic Exception Handling

fn divide(a: Int, b: Int) raises -> Int:
    if b == 0:
        raise Error("Division by zero")
    return a // b

fn safe_divide(a: Int, b: Int) -> Int:
    try:
        return divide(a, b)
    except e:
        print("Error:", e)
        return 0

Exception Handling Components

try Block

Defines sections where exceptions might occur.

except Clause

Catches and handles errors. The caught error object provides access to messages and stack traces.

try:
    risky_operation()
except e:
    print("Error message:", e)
    print("Stack trace:", e.get_stack_trace())

else Clause

Executes only if no exception was raised in the try block.

try:
    result = computation()
except:
    print("Failed")
else:
    print("Success:", result)

finally Clause

Guarantees execution regardless of exceptions, ideal for cleanup.

fn process_file(path: String) raises:
    var file = open(path)
    try:
        data = file.read()
        process(data)
    finally:
        file.close()  # Always executes

Raising Exceptions

# Raise with string message
raise "Something went wrong"

# Raise with Error object
raise Error("Detailed error message")

Context Managers

Types implementing __enter__() and __exit__() methods work with with statements. 

struct FileHandle:
    var path: String
    
    fn __enter__(self) -> Self:
        # Setup logic
        return self
    
    fn __exit__(self):
        # Cleanup logic - guaranteed to run
        self.close()

# Usage
with FileHandle("data.txt") as file:
    file.process()
    # __exit__ called automatically, even on error/break/continue/return
Guarantee: The __exit__() method is guaranteed to run even if the block terminates due to break, continue, return, or an exception.

8. Traits System

Traits define interfaces through required method prototypes. Structures conform by implementing these methods, enabling generic programming.

Defining and Using Traits

trait Drawable:
    fn draw(self):
        pass

struct Circle(Drawable):
    var radius: Float64
    
    fn draw(self):
        print("Drawing circle with radius:", self.radius)

fn render[T: Drawable](shape: T):
    shape.draw()

Trait Compositions

Combine multiple traits using &:

fn process[T: Copyable & Movable & Stringable](value: T):
    var copy = value  # OK: Copyable
    print(value)      # OK: Stringable

Trait Inheritance

Traits can extend other traits, creating hierarchies:

trait Comparable(EqualityComparable):
    fn __lt__(self, other: Self) -> Bool:
        pass
    fn __le__(self, other: Self) -> Bool:
        pass
    fn __gt__(self, other: Self) -> Bool:
        pass
    fn __ge__(self, other: Self) -> Bool:
        pass

# Implementers must satisfy both Comparable and EqualityComparable

Default Method Implementations

Traits can provide default implementations that conforming types can inherit:

trait Iterator:
    alias ElementType: AnyType
    
    fn __next__(mut self) -> Optional[Self.ElementType]:
        pass
    
    fn __has_next__(self) -> Bool:
        pass
    
    # Default implementation
    fn count(self) -> Int:
        var n = 0
        while self.__has_next__():
            _ = self.__next__()
            n += 1
        return n

Associated Types and Aliases

Traits can declare associated type aliases or default values:

trait Container:
    alias ElementType: AnyType
    alias DefaultCapacity = 16
    
    fn __len__(self) -> Int:
        pass
    
    fn __getitem__(self, index: Int) -> Self.ElementType:
        pass

Register-Passable Traits

Requirements:

  • @register_passable traits: Conforming structs must be @register_passable or @register_passable("trivial")
  • @register_passable("trivial") traits: Conforming structs must be @register_passable("trivial")

Automatic Conformance:

  • @register_passable structs: Automatically conform to Movable
  • @register_passable("trivial") structs: Automatically conform to both Copyable and Movable

Built-in Traits

Lifecycle & Ownership

Copyable copy() Explicit duplication (v24.6 revised)
ImplicitlyCopyable Inherits copy() Implicit copying via assignment

Representation & Conversion

Representable __repr__() repr() (v24.4)

Intable __int__() int() conversion

Comparison & Ordering

Trait Methods Operators
EqualityComparable __eq__(), __ne__() ==, !=

Collection-Specific

  • KeyElement: For Dict keys and Set elements (hashable + equality)
  • Iterator: Types implementing __iter__() and __next__()

9. Parametric Programming

Alias Declarations

Defines compile-time values for type aliases and parameter values:

# Type aliases
alias IntList = List[Int]
alias FloatPair = Tuple[Float64, Float64]

# Parameter values both alias and comptime can be used.. 
# both are same but just the keyword differences
alias SIMD_WIDTH = 8
comptime MAX_SIZE = 1024

# Local aliases in functions
fn compute():
    alias nelts = 4
    var data = SIMD[DType.float32, nelts]()

Parametric Aliases (v25.5+)

Aliases with their own parameter lists:

alias doubled[x: Int] = x * 2
alias VectorOf[T: AnyType, n: Int] = SIMD[T, n]

# Usage
alias four = doubled[2]
var vec: VectorOf[DType.int32, four]

Parameter Expressions

Execute at compile time, producing compile-time constants:

# Compile-time computation
alias optimal_width = compute_simd_width()

# Parametric function
fn matrix_multiply[M: Int, N: Int, K: Int](
    a: Matrix[M, K],
    b: Matrix[K, N]
) -> Matrix[M, N]:
    # M, N, K are compile-time constants
    pass

@parameter Decorator

Marks functions and closures for compile-time execution:

@parameter
fn compile_time_factorial[n: Int]() -> Int:
    @parameter
    if n <= 1:
        return 1
    return n * compile_time_factorial[n - 1]()

# Result is compile-time constant
alias fact_5 = compile_time_factorial[5]()  # 120

Generic Programming Patterns

fn swap[T: Movable](mut a: T, mut b: T):
    var temp = a^
    a = b^
    b = temp^

fn find_max[T: Comparable](values: List[T]) -> Optional[T]:
    if len(values) == 0:
        return None
    
    var max_val = values[0]
    for item in values:
        if item > max_val:
            max_val = item
    return max_val

Field Declarations

struct Person:

    var email: String = ""  # Field initializer

Note: Field order affects memory layout. Static fields (aliases) consume no instance storage.

Method Declarations

Instance Methods

struct Counter:
    var value: Int
    
    fn increment(mut self):
        self.value += 1
    
    fn get_value(self) -> Int:
        return self.value
    
    fn consume(owned self):
        # Takes ownership, self destroyed after

Static Methods

struct MathUtils:
    @staticmethod
    fn add(a: Int, b: Int) -> Int:
        return a + b

    fn create_default() -> Self:

Generic Methods

struct Container[T: AnyType]:
    var data: T
    
    fn transform[U: AnyType](self, func: fn(T) -> U) -> Container[U]:
        return Container[U](func(self.data))

Special Methods and Operator Overloading

Arithmetic Operators

struct Vector2:
    var x: Float64
    var y: Float64
    
    fn __add__(self, other: Self) -> Self:
        return Self(self.x + other.x, self.y + other.y)
    
    fn __sub__(self, other: Self) -> Self:
        return Self(self.x - other.x, self.y - other.y)
    
    fn __mul__(self, scalar: Float64) -> Self:
        return Self(self.x * scalar, self.y * scalar)

Comparison Operators

fn __eq__(self, other: Self) -> Bool:
    return self.x == other.x and self.y == other.y

fn __ne__(self, other: Self) -> Bool:
    return not (self == other)

fn __lt__(self, other: Self) -> Bool:
    return self.magnitude() < other.magnitude()

Container Operations

struct DynamicArray[T: AnyType]:
    var data: UnsafePointer[T]
    var size: Int
    
    fn __getitem__(self, index: Int) -> T:
        return self.data[index]
    
    fn __setitem__(mut self, index: Int, value: T):
        self.data[index] = value
    
    fn __len__(self) -> Int:
        return self.size

Iteration Support

struct Range(Iterable):
    var start: Int
    var end: Int
    
    fn __iter__(self) -> RangeIterator:
        return RangeIterator(self.start, self.end)

struct RangeIterator:
    var current: Int
    var end: Int
    
    fn __next__(mut self) -> Optional[Int]:
        if self.current < self.end:
            var value = self.current
            self.current += 1
            return value
        return None
    
    fn __has_next__(self) -> Bool:
        return self.current < self.end

Callable Types

struct Accumulator:
    var total: Int
    
    fn __call__(mut self, value: Int) -> Int:
        self.total += value
        return self.total

# Usage
var acc = Accumulator(0)
print(acc(5))   # 5
print(acc(10))  # 15

Parameterized Structs

struct GenericArray[ElementType: Copyable & Movable]:
    var data: UnsafePointer[ElementType, MutOrigin.external]
    var size: Int
    var capacity: Int

    fn __init__(out self, capacity: Int = 16):
        self.size = 0
        self.capacity = capacity
        self.data = UnsafePointer[ElementType].alloc(capacity)

    fn __init__(out self, var *elements: ElementType):
        self.size = len(elements)
        self.capacity = self.size
        self.data = UnsafePointer[ElementType].alloc(self.size)
        
        for i in range(self.size):
            (self.data + i).init_pointee_move(elements[i])

    fn __del__(deinit self):
        for i in range(self.size):
            (self.data + i).destroy_pointee()
        self.data.free()

    fn __getitem__(self, i: Int) raises -> ref [self] ElementType:
        if i < self.size:
            return self.data[i]
        else:
            raise Error("Index out of bounds")

# Usage
var int_array = GenericArray[Int](1, 2, 3, 4)
var float_array = GenericArray[Float64](1.0, 2.0, 3.0)

Using the Self Type

Within a parameterized struct, Self represents a concrete instance with all parameters specified:

struct Stack[T: Copyable & Movable]:
    var items: List[T]
    
    @staticmethod
    fn create_empty() -> Self:
        return Self(List[T]())
    
    fn clone(self) -> Self:
        return Self(self.items.copy())

11. Advanced Memory Management

UnsafePointer: Low-Level Memory Access

Provides direct, manual control over memory with no safety guarantees. Similar to raw pointers in C/C++.

Memory Lifecycle States

  1. Null: References no memory
  2. Allocated but Uninitialized: Memory reserved, dereferencing is undefined behavior
  3. Initialized: Contains valid value, safe to access
  4. Dangling: Memory freed, dereferencing is undefined behavior

Manual Memory Management Operations

# 1. Allocate memory
var ptr = UnsafePointer[Int].alloc(10)

# 2. Initialize values
for i in range(10):
    (ptr + i).init_pointee_copy(i * 2)

# 3. Access data
for i in range(10):
    print(ptr[i])

# 4. Destroy values
for i in range(10):
    (ptr + i).destroy_pointee()

# 5. Deallocate memory
ptr.free()

Advanced Operations

# Move value from pointer
var value = ptr.take_pointee()  # Leaves memory uninitialized

# Transfer value to another location
ptr.move_pointee_into(dst_ptr)  # dst_ptr must be uninitialized

# Pointer arithmetic
var next_ptr = ptr + 3
next_ptr += 1
Critical: Direct assignment (ptr[] = x) before initialization is undefined behavior. Always use init_pointee_copy() or init_pointee_move() first.

OwnedPointer: Exclusive Heap Ownership

Smart pointer managing a single heap-allocated value with automatic lifecycle management.

Characteristics:

  • Exclusive ownership (move-only semantics)
  • Automatic allocation and deallocation
  • Cannot be copied, only moved
struct LargeData:
    var buffer: List[Float64]
    # ... large data structure

fn process():
    # Allocates on heap, moves into pointer
    var owned = OwnedPointer(LargeData())
    
    # Access value
    owned[].compute()
    
    # Transfer ownership
    var other = owned^  # owned is now invalid
    
    # Automatic cleanup when other goes out of scope

ArcPointer: Shared Reference Counting

Thread-safe smart pointer with atomic reference counting for shared ownership.

Key Features:

  • Multiple owners can share the same value
  • Automatic cleanup when last reference is dropped
  • Low-cost copying (only increments count)
  • Thread-safe reference count updates
struct SharedData:
    var config: ArcPointer[Dict[String, String]]
    
    fn __init__(out self):
        var cfg = Dict[String, String]()
        cfg["version"] = "1.0"
        self.config = ArcPointer(cfg)
    
    fn __copyinit__(out self, other: Self):
        # Cheap copy: only increments reference count
        self.config = other.config
    
    fn update(mut self, key: String, value: String):
        # All copies share this modification
        self.config[][key] = value

# Usage
var data1 = SharedData()
var data2 = data1  # Shares the same Dict
data1.update("status", "active")
print(data2.config[]["status"])  # Prints: active
Thread Safety Note: Only reference count updates are atomic. Concurrent modification of the shared value requires additional synchronization.

Pointer: Safe Non-Owning References

Safe pointer that references a value without taking ownership, with lifetime tracking.

fn process_data(ptr: Pointer[Int, origin]):
    # Can read/write through pointer safely
    ptr[] += 10

var value = 42
var ptr = Pointer(to=value)
process_data(ptr)
print(value)  # 52

Bitcasting and SIMD Operations

Pointer Bitcasting

Reinterprets memory at the same address with a different type:

fn read_binary_data(ptr: UnsafePointer[UInt8]) -> List[UInt32]:
    var results = List[UInt32]()
    var offset = 0
    
    # Read length byte
    var length = Int(ptr[offset])
    offset += 1
    
    # Bitcast to read UInt32 values
    var uint32_ptr = (ptr + offset).bitcast[UInt32]()
    
    for i in range(length):
        results.append(uint32_ptr[i])
    
    return results

Endianness Handling

from sys import byte_swap

fn read_big_endian_int(ptr: UnsafePointer[UInt8]) -> UInt32:
    var uint32_ptr = ptr.bitcast[UInt32]()
    var value = uint32_ptr[]
    
    # Convert from big-endian if needed
    @parameter
    if sys.is_little_endian():
        return byte_swap(value)
    return value

Vectorized Memory Operations

# Strided load/store - access non-contiguous elements
fn process_rgb_channel(ptr: UnsafePointer[UInt8], pixel_count: Int):
    alias simd_width = 8
    var stride = 3  # RGB: 3 bytes per pixel
    
    for i in range(0, pixel_count * stride, simd_width * stride):
        # Load red channel (every 3rd byte)
        var red = ptr.offset(i).strided_load[width=simd_width](stride)
        
        # Process (e.g., invert)
        var inverted = ~red
        
        # Store back
        ptr.offset(i).strided_store[width=simd_width](inverted, stride)

# Gather/scatter - irregular access patterns
fn permute_data(src: UnsafePointer[Float32], dst: UnsafePointer[Float32]):
    alias width = 8
    var indices = SIMD[DType.int32, width](7, 3, 5, 1, 6, 2, 4, 0)
    
    # Gather from non-contiguous locations
    var values = src.gather(indices)
    
    # Process
    values *= 2.0
    
    # Scatter to non-contiguous locations
    dst.scatter(values, indices)

Memory Management Best Practices

Safety Hierarchy:
  1. Prefer stack allocation and automatic memory management
  2. Use OwnedPointer for single ownership
  3. Use ArcPointer for shared ownership
  4. Use Pointer for safe non-owning references
  5. Use Span for safe views of contiguous memory
  6. Use UnsafePointer only when necessary (FFI, custom allocators)

Common Patterns

# Custom allocator using UnsafePointer
struct Arena[T: AnyType]:
    var memory: UnsafePointer[T]
    var capacity: Int
    var used: Int
    
    fn __init__(out self, capacity: Int):
        self.capacity = capacity
        self.used = 0
        self.memory = UnsafePointer[T].alloc(capacity)
    
    fn allocate(mut self) raises -> Pointer[T]:
        if self.used >= self.capacity:
            raise Error("Arena full")
        
        var ptr = self.memory + self.used
        self.used += 1
        return Pointer(to=ptr[])
    
    fn reset(mut self):
        # Destroy all allocated objects
        for i in range(self.used):
            (self.memory + i).destroy_pointee()
        self.used = 0
    
    fn __del__(deinit self):
        self.reset()
        self.memory.free()

12. MLIR Interoperability

Mojo provides direct access to MLIR (Multi-Level Intermediate Representation), enabling low-level control and hardware-specific optimizations without modifying the compiler.

Understanding MLIR in Mojo

Mojo uses ahead-of-time (AOT) compilation, first translating source code into MLIR intermediate representation before generating machine code. Unlike custom IRs, MLIR is extensible and supports multiple languages and processor types.

MLIR Structure

  • Dialects: Namespaces for related operations
  • Operations: Represent computations or abstractions
  • Operands: Operation inputs (like arguments)
  • Results: Operation outputs
  • Attributes: Compile-time constants and metadata
  • Types: Associated with operands, results, and attributes

MLIR Elements in Mojo

Mojo exposes MLIR through three primary interfaces:

1. __mlir_attr (Attributes)

Define MLIR attributes (compile-time constants) with their types:

alias _0 = __mlir_attr.`0:i1`  # Constant 0 of type i1
alias _1 = __mlir_attr.`1:i1`  # Constant 1 of type i1
alias default_val = __mlir_attr.`42`  # Defaults to i64 if type omitted

# Complex attribute example
alias false_attr = __mlir_attr.`false`

2. __mlir_type (Types)

Reference MLIR types directly:

struct BitList(Stringable):
    var value: List[__mlir_type.i1]  # List of MLIR i1 (1-bit) values
    
    fn __init__(out self, *values: __mlir_type.i1):
        self.value = List[__mlir_type.i1]()
        for i in values:
            self.value.append(i)
    
    fn __str__(self) -> String:
        var s = String("0b")
        for i in self.value:
            # Cast i1 to index type for Int conversion
            var int_val = __mlir_op.`index.castu`[
                _type=__mlir_type.index
            ](i)
            s += String(Int(mlir_value=int_val))
        return s

# Usage
var bits = BitList(_0, _1, _0, _1)
print(bits)  # Output: 0b0101

3. __mlir_op (Operations)

Invoke MLIR operations directly. Operations have the form <dialect>.<operation>: 

# Boolean constant operation
@register_passable("trivial")
struct CustomBool:
    var value: __mlir_type.i1
    
    fn __init__(out self, val: Bool):
        
        if val:
            self.value = __mlir_op.`index.bool.constant`[
                value = __mlir_attr.`true`
            ]()
        else:
            self.value = __mlir_op.`index.bool.constant`[
                value = __mlir_attr.`false`
            ]()
    
    fn __mlir_i1__(self) -> __mlir_type.i1:
        return self.value

# Usage in conditionals
var flag = CustomBool(True)
if flag:
    print("Flag is true")
Syntax Note: Use backticks when operation names contain characters not allowed in Mojo identifiers (like .).

POP Dialect

The POP (Parametric Operations) dialect provides hardware-aware, parametric operations on top of the LLVM dialect.

Core POP Types

Type Description Example
pop.simd SIMD vector type !pop.simd<4, si32>
pop.scalar Scalar type (1-element SIMD) !pop.scalar<f32>
pop.array Fixed-size array !pop.array<4, f32>
pop.union Non-discriminated union !pop.union<i32, i64>
pop.int_literal Arbitrary-precision integer Compile-time only
pop.float_literal Arbitrary-precision float Compile-time only

Type Conversions

fn mixed_operations(arg: Float32) -> Float32:
    # Convert POP type to builtin for LLVM operations
    var builtin_val = __mlir_op.`pop.cast_to_builtin`[
        _type=__mlir_type.f32
    ](arg)
    
    # Use LLVM operation
    var result = __mlir_op.`llvm.fadd`(builtin_val, builtin_val)
    
    # Convert back to POP type
    var pop_result = __mlir_op.`pop.cast_from_builtin`[
        _type=__mlir_type.`!pop.scalar`
    ](result)
    
    return pop_result

Common POP Operations

# Arithmetic
var sum = __mlir_op.`pop.add`(a, b)
var product = __mlir_op.`pop.mul`(a, b)
var fused = __mlir_op.`pop.fma`(a, b, c)  # a * b + c

# Comparison
var is_greater = __mlir_op.`pop.cmp`[
    predicate = __mlir_attr.`#pop`
](a, b)

# Memory operations
var ptr = __mlir_op.`pop.aligned_alloc`[
    alignment = 64._mlir_value
](size._mlir_value)

__mlir_op.`pop.store`(value, ptr)
var loaded = __mlir_op.`pop.load`(ptr)

# Array operations
var arr = __mlir_op.`pop.array.create`(x, y, z)

Benefits of MLIR Integration

Key Advantages:
  • Hardware Abstraction: Write high-level code that compiles to optimal hardware-specific instructions
  • Extensibility: Add custom operations without modifying the compiler
  • Zero-Cost Abstractions: High-level abstractions compile to efficient low-level code
  • Interoperability: Seamless integration with existing MLIR-based tools and frameworks
  • Future-Proof: Automatic support for new hardware through MLIR's extensible dialect system

When to Use MLIR Directly

  • Hardware-Specific Optimizations: Access specialized instructions not exposed by standard library
  • FFI Integration: Interface with external libraries at the LLVM level
  • Custom Type Systems: Implement domain-specific types with specialized behavior
  • Compiler Extensions: Experiment with new language features before they're standardized
  • Performance Tuning: Fine-tune code generation for specific workloads

    raise "Some Error"  # Passes if contains "Error"

Automatic test discovery and execution. Supports skipping, reporting (v0.25.7).

from testing import TestSuite

fn test_add() raises:
    assert_equal(2 + 2, 4)

fn main() raises:
    var suite = TestSuite()

    suite.add_test(test_fail)
    var report = suite.run()

17. Standard Library: Runtime Module

The runtime module handles concurrency and tracing.

AsyncRT: Asynchronous Runtime

Low-level concurrency with tasks and groups. Device-aware scheduling (v0.25+).

Key Types

Type Description
Task[T] Asynchronous task producing T
TaskGroup Group for concurrent tasks
DeviceContextPtr Pointer to C++ device context for GPU 
from runtime.asyncrt import create_task, TaskGroup

fn async_work() -> Int:
    return 42

var task = create_task(async_work())
print(task.await())  # 42

var group = TaskGroup()
group.add_task(create_task(async_work))
group.wait()  # Wait for all

Best Practices and Design Guidelines

Memory Safety

  • Prefer safe pointers and automatic memory management
  • Use Span for safe, bounds-checked memory views
  • Always initialize memory before access
  • Match allocations with deallocations
  • Leverage ASAP destruction for timely resource cleanup
  • Use origin tracking to ensure reference validity

Performance Optimization

  • Use SIMD types for data-parallel operations
  • Leverage compile-time parameters for zero-cost abstractions
  • Apply @always_inline to small, critical functions
  • Use @parameter for for loop unrolling
  • Prefer register-passable types for small values
  • Minimize heap allocations in hot paths
  • Use strided and gather/scatter operations for SIMD efficiency

Code Organization

  • Define clear interfaces using traits
  • Implement appropriate lifecycle traits (Copyable, Movable)
  • Use @deprecated for API migrations
  • Group related functionality with static methods

Error Handling

  • Use raises for operations that can fail
  • Implement context managers for resource management
  • Use Optional for values that may be absent
  • Use Variant for tagged unions and result types
  • Always clean up resources in finally blocks
  • Provide meaningful error messages with context

Generic Programming

  • Use trait bounds to constrain type parameters
  • Leverage parametric aliases for type convenience
  • Prefer compile-time dispatch over runtime polymorphism
  • Use @parameter for compile-time computation
  • Document type parameter requirements clearly
